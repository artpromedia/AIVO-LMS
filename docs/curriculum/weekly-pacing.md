# Calendar-driven weekly pacing (Phase 2)

Turns a learner's district/grade **scope-&-sequence** (generated by brain-svc's
AI curriculum engine) into a **dated, week-by-week plan** aligned to a school
calendar, so the tutor can serve the right topics each week and **pause
instruction over breaks**. This is the automated counterpart to Phase 1's manual
"This week at school" upload: it works even when no parent/teacher uploads a
syllabus.

## Tables (shared Postgres)

- `school_calendars` — learner-scoped calendar (academic year, timezone).
- `school_calendar_terms` — term boundaries (`term_number`, start/end date).
- `school_calendar_breaks` — holidays / breaks / summer (`kind`, start/end date).
- `learner_pacing_plans` — one active plan per (learner, subject); holds the
  source scope-&-sequence + plan start date + status (`active`/`archived`).
- `learner_pacing_weeks` — the exploded dated weeks: `week_index`, `week_start`,
  `week_end`, `kind` (`instruction`/`break`/`holiday_prep`), `term_number`,
  `unit_title`, `topics`, `standards`, `objectives`, `vocabulary`, `status`.

## Pacing engine (pure, deterministic)

`build_pacing_weeks(scope_sequence, breaks, plan_start)`:

1. `flatten_unit_weeks` expands each `term → unit` into one "unit-week" per
   `duration_weeks` (a 3-week unit → 3 unit-weeks).
2. It walks the calendar one 7-day week at a time from `plan_start`. If a week
   overlaps a break it emits a `kind="break"` placeholder and **does not consume
   an instructional unit-week** (instruction pauses); otherwise it assigns the
   next unit-week as `kind="instruction"`.
3. Stops once every instructional unit-week is placed.

Side-effect free (no DB, no LLM) so it's unit-tested deterministically. Break
weeks are emitted (not skipped) so Phase 4 can fill them with holiday-prep
content.

## Routes (`/api/brain/pacing`, JWT-auth + learner-scope)

| Method | Route | Purpose |
| ------ | ----- | ------- |
| `POST` | `/{learner_id}/pacing-plan/generate` | generate scope-&-sequence → explode onto the calendar → persist a new active plan (archiving the prior one). Body: `{ subject, term_count?, plan_start, calendar?: { terms[], breaks[] } }`. |
| `GET`  | `/{learner_id}/pacing/current?subject=&on=` | the week whose window contains `on` (default today) for the active plan, plus the next week. |
| `GET`  | `/{learner_id}/pacing/plan?subject=` | the full active plan with all weeks. |

The plan reuses the existing `generate_scope_sequence` (brain-svc curriculum
engine), the learner's framework/grade/mastery/accommodations, and persists via
raw SQL (same pattern as `routes/curriculum.py`).

## Lesson consumption (Phase 2b — implemented)

The pacing plan now actually drives lessons. `getActiveCurriculumFocus`
(`apps/web-v2/lib/db/repos.ts`) resolves the focus the tutor teaches to with
this priority:

1. **Manual upload (Phase 1)** — a parent/teacher "this week at school" upload
   from tutor-svc wins (the explicit signal).
2. **Automated pacing (Phase 2)** — if there's no manual upload, web-v2 reads
   brain-svc's current instructional week and maps it to a `CurriculumFocus`.

Wiring:

- **brain-svc service-token auth** (`services/brain-svc/.../auth.py`): `require_auth`
  now accepts the shared `INTERNAL_SERVICE_TOKEN` via `x-service-token` and
  returns a `service` principal (mirrors tutor-svc). `verify_learner_access`
  already trusts the `service` role; the calling BFF enforced learner-scope.
- **web-v2 proxy** (`apps/web-v2/lib/bff/brain-pacing.ts`): server-side client for
  `…/pacing/current`. `weekToFocus` maps an `instruction` week to a focus
  (topics, vocabulary→keywords, standards, objectives→skills, `confidence: 1`).
  A `break` week returns **null** (holidays are the Phase 4 track, not a normal
  lesson). `brainPacingFocusSafe` never throws — a brain-svc outage or unset
  token degrades to no-sync.
- Config (web-v2 env): `BRAIN_SVC_URL` (default `http://localhost:3081`) +
  `INTERNAL_SERVICE_TOKEN` (shared secret). When the token is unset the pacing
  fallback is disabled (dev), so the app still runs without brain-svc.
- Tests: `apps/web-v2/lib/bff/brain-pacing.test.ts` (mapping, break-skip, safe
  read, token gating).
