# GEO Playbook — making AIVO citable by answer engines

**GEO** (Generative Engine Optimization) is SEO's sibling for AI answer engines
— ChatGPT, Perplexity, Claude, and Google AI Overviews / Gemini. Where SEO
optimizes for a ranked list of blue links, GEO optimizes for being **read,
attributed, and quoted** inside a generated answer. This playbook is the
source of truth for how the marketing site stays legible to those engines.

It is enforced in CI by `.github/workflows/marketing-geo.yml`, which blocks
merge on invalid/missing structured data or a broken `llms.txt`.

---

## 1. `llms.txt` — the agent manifest

We serve two static, `text/plain` manifests (Next route handlers under
`apps/marketing/src/app/`):

- **`/llms.txt`** — H1 site name, a 2-3 sentence summary, then sectioned
  markdown links to canonical URLs (`## Products`, `## For audiences`,
  `## Pricing & trials`, `## Compliance`, `## Guides`).
- **`/llms-full.txt`** — the same link set plus inlined, factual, quotable
  value-prop copy (what AIVO is, Brain Clone, 14 tutors, 5 functioning levels,
  COPPA/FERPA posture, pricing and trial terms). This is the body LLMs cite,
  so keep it factual — no marketing fluff.

Both are generated by `apps/marketing/src/lib/llms-content.ts`, which sources
its link set from the **same data modules the sitemap uses** (`AUDIENCES`,
`LEVELS`, `SUBJECTS`, `COMPARISONS`, `TUTORS`). They are **not** added to
`sitemap.ts` — they are agent manifests, not indexable pages.

**Drift guard:** `lib/__tests__/llms-content.test.ts` asserts every
audience/subject/level slug appears in `llms.txt`. If you add a page type,
update `llms-content.ts` and the test stays green.

## 2. AI crawlers — who we allow and why

`apps/marketing/src/app/robots.ts` emits one group per named AI crawler (driven
by the exported `AI_CRAWLERS` array) **in addition** to the `*` group. Every
group allows content but denies `DISALLOWED_PATHS` (`/api/`, `/login`,
`/signup`).

| Bot                                                     | Operator   | Why allow                              |
| ------------------------------------------------------- | ---------- | -------------------------------------- |
| `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`               | OpenAI     | Training, ChatGPT search, live fetch   |
| `ClaudeBot`, `anthropic-ai`, `Claude-Web`               | Anthropic  | Training + live retrieval              |
| `PerplexityBot`                                         | Perplexity | Answer-engine grounding                |
| `Google-Extended`                                       | Google     | Gemini / AI Overviews use of content   |
| `Applebot-Extended`, `Amazonbot`, `Bytespider`, `CCBot` | Various    | We want to be citable; content allowed |

We **allow content** because being read is the whole point of GEO; we keep auth
and API paths denied for every bot. To change our stance for one engine, edit
`AI_CRAWLERS` (or give it a bespoke group) — it is the single knob.

## 3. Structured data each page type must emit

Use the shared `components/seo/JsonLd.tsx` component — never hand-roll inline
`<script type="application/ld+json">`.

| Page type                                        | Required JSON-LD types                           | Built by                |
| ------------------------------------------------ | ------------------------------------------------ | ----------------------- |
| Home (`/`)                                       | `Organization`, `WebSite`, `SoftwareApplication` | `app/layout.tsx`        |
| Audience / level / subject / compare / guide hub | `BreadcrumbList`                                 | `LandingPageLayout`     |
| Audience page                                    | + `FAQPage`                                      | `AudiencePage`          |
| Blog post                                        | `BlogPosting` + `BreadcrumbList`                 | `lib/article-schema.ts` |
| Guide (non-procedural)                           | `Article` + `BreadcrumbList`                     | `lib/article-schema.ts` |
| Guide (procedural)                               | `HowTo` (with `HowToStep[]`) + `BreadcrumbList`  | `lib/article-schema.ts` |

Citable entities (`Article`/`BlogPosting`/`HowTo`) **must** carry non-null
`author`, `datePublished`, `dateModified`, `publisher`, `image`, and
`mainEntityOfPage` — these are the exact fields engines use to attribute and
cite by name. A guide becomes procedural by setting the `howTo` field on its
entry in `lib/content.ts`.

---

## 4. The "Key takeaways" authoring rule

Every blog post and guide opens with a **Key takeaways** block: 3-5 short,
self-contained, factual claims. Answer engines preferentially quote concise,
standalone sentences, so each takeaway must stand on its own without the
surrounding paragraph. They live in the required `keyTakeaways` field on each
article in `lib/content.ts` and render at the top of `ArticleView`.

Rules:

- 3-5 bullets, each a complete sentence that is true out of context.
- Lead with the claim, not throat-clearing ("AIVO does not use learner data
  to train third-party models" — not "It's worth noting that…").
- No marketing superlatives; state what is verifiably true.

---

## 5. Freshness signal

`sitemap.ts` emits a **real** `lastModified` for dated content (blog/guide,
from `updatedAt ?? publishedAt`) rather than a blanket `now()`. Freshness is a
ranking and citation signal, so set `updatedAt` when you meaningfully revise a
post.

---

## 6. CI gate

`marketing-geo.yml` runs on PRs touching `apps/marketing`, `packages/brand`, or
`scripts/geo`. It:

1. runs the GEO unit tests (`pnpm --filter @aivo/marketing test`);
2. builds and boots the marketing server;
3. runs `scripts/geo/validate-structured-data.mjs` against representative URLs
   (home, an audience page, a blog post, a procedural guide, pricing), failing
   on invalid or missing required JSON-LD;
4. runs `scripts/geo/check-llms-txt.mjs`, asserting `/llms.txt` is non-empty,
   has every required section header, and every link is reachable.

If you add a representative-page type, extend `EXPECTATIONS` in
`scripts/geo/validate-structured-data.mjs`.
