1. Cross-cutting findings (all 3 dashboards)
1.1 Near-duplicate layouts — 3× copy-paste drift
The three layout.tsx files are nearly identical (103 lines each) differing only by accent color (blue/pink/green), nav items, and role label. This is 309 lines of code that should be one shared CareTeamLayout component in packages/shared-ui (or apps/web/src/components/layouts/). Any a11y fix must be applied three times today.

1.2 "Save Preferences" does not save
teacher/settings/page.tsx:18-21 — handleSaveSettings only flips a local settingsSaved state and sets a 3-second timeout. No API call. Same pattern in therapist/settings/page.tsx and caregiver/settings/page.tsx. This is a user-trust regression: a parent/therapist changes alert preferences, sees "Settings saved!", and nothing persists.

1.3 Four "Coming Soon" stubs shipped to production routes
teacher/lesson-plans/page.tsx (26 lines)
therapist/sessions/page.tsx (26 lines)
caregiver/observations/page.tsx (26 lines)
caregiver/sessions/page.tsx (26 lines)
All four are navigable from the sidebar but do nothing. This is worse than hiding them — users click, lose trust, and don't come back. Either implement (preferred) or feature-flag and hide from nav.

1.4 Wrong i18n namespace (real bug)
therapist/page.tsx:26 → useTranslations("caregiver") (should be "therapist")
therapist/reports/page.tsx:25 → useTranslations("caregiver") (should be "therapist")
Therapist dashboard is silently reading caregiver translations. Will mis-translate on every locale.

1.5 Mobile is effectively broken
The sidebar is w-64 or w-16 with no mobile hamburger, no breakpoint collapse, and no overlay mode. On a ~375px viewport, the sidebar consumes 68% of width and content overflows. None of the three dashboards has a responsive nav pattern.

1.6 atRiskCount declared, never computed
teacher/page.tsx:47-53 builds ClassroomGroup with atRiskCount: 0 but never populates it, and the UI never reads it. Either delete the field or implement the logic — half-built data shapes are confusing.

1.7 Hardcoded "Active" status
teacher/reports/page.tsx:103 renders every learner with a green "Active" pill regardless of actual status. Misleading; fails the visual source-of-truth test.

1.8 Expand-card pattern has a11y gaps
Teacher (page.tsx:126-131) and Therapist (page.tsx:114-120) both use a <div role="button" tabIndex={0} onClick ... onKeyDown> pattern. Issues:

No visible focus ring in Tailwind classes — relies on browser default which is often invisible on white cards.
onClick fires on the full card including its inner brain-viz area; clicking inside the expanded viz collapses the card.
Semantic: a real <button> inside the card wrapping only the header region is better.
1.9 No retry on fetch errors
All three pages show <p>Please try refreshing the page.</p> — no actual Retry button. Poor UX and fails the "no dead ends" principle.

1.10 No empty-state CTA
When learners.length === 0, all three dashboards render an explanatory paragraph but no link/button. Therapist for example reads "Parents can invite you to their learner's care team from the Collaboration page in their dashboard." — the therapist cannot act. They need at minimum: a copyable invite-code entry field, or a link to /dashboard/notifications to see pending invites.

1.11 BrainVisualization re-fetches on every expand
BrainVisualization learnerId={l.id} is mounted fresh each time a card expands, causing a new API call. With a teacher of 30 learners clicking around, that's 30+ redundant /api/brain/:learnerId calls per session. Needs memoization or move to a data layer cache (SWR/React Query).

1.12 No search / sort / filter
Teacher page with 40 students — no way to find one. Therapist caseload — no category/goal-status filter. Caregiver with multiple kids — only a raw <select>.

1.13 No communication / collaboration affordances
None of the three dashboards let these users:

Message the parent
Add a note to a learner's record
Request an observation
Upload a document (IEP, assessment, progress report)
The platform has family-svc and comms-svc for exactly this. It's a gap, not an absence of capability.

1.14 No quick actions on learner card
No "view gradebook", "open brain profile in new tab", "see recent sessions", "schedule a session". Each learner card is a dead-end once expanded.

1.15 Loading is opacity-pulse, not skeleton
animate-pulse text-slate-500 for all loading states. A skeleton would communicate structure and reduce perceived wait.

2. Teacher-specific findings
2.1 Grade-group logic is fragile
teacher/page.tsx:46-53 buckets learners by gradeLevel string. An "Unassigned" grade merges with learners whose gradeLevel is missing; 1st vs. 1st grade vs. "1" won't merge. Needs normalization (normalizeGrade()).

2.2 Reports table lacks accessible table structure
teacher/reports/page.tsx:82-110:

No <caption> (therapist reports has one, this one doesn't).
<th> elements lack scope="col".
No row headers via <th scope="row"> on learner name.
2.3 Reports "cards" are not interactive despite looking clickable
Lines 34-75 — four report cards have hover effects (hover:shadow-sm hover:border-blue-300) that suggest clickability, but they're plain <div>s with no links or onClick. Users click and nothing happens. Either make them real links (where do they go?) or strip hover affordance.

2.4 No class/grade-level actions
Teacher sees grade groups but can't:

Create a lesson plan for an entire group
Run an activity across a group
Export a grade-level report
The lesson-plans stub promises "AI-powered lesson plan generation based on your learners' Brain Clone profiles" — but there's no entry point from the group header.

3. Therapist-specific findings
3.1 Goals display is capped at 2 with no "expand to see all" affordance
therapist/page.tsx:134 — goals.slice(0, isExpanded ? undefined : 2) works, but collapsed state shows "+N more goals" as a paragraph, not a button. User tapping the "+N more" text triggers the card expand, which is implicit and confusing.

3.2 No goal category taxonomy
Goals are grouped only by learner, never by category (speech, OT, PT, SEL). A therapist with a caseload of 15 wants to see "all speech-articulation goals" across clients.

3.3 No progress trend
Goal progress shows a bar but no sparkline, no "last updated", no "at what rate". Therapy goals demand trend visualization — this is the core clinical value.

3.4 Session tracking is a stub
therapist/sessions/page.tsx is "Coming Soon" but session tracking is fundamental to therapy billing and progress documentation. This is the most critical gap in the therapist surface.

3.5 No SOAP/DAP note capability

3.6 Reports table progress bar is thin
therapist/reports/page.tsx:79-81 — h-1.5 progress bar. At 96dpi that's ~2px. Too thin for aging eyes; harder to hit visually for low-vision users.

caregiver/page.tsx:47 auto-selects the first learner. Mental model is "I'm viewing one kid at a time" — but there's no visual anchor showing the active learner at the top of the layout. The H1 is generic {t("dashboard")}, learner name appears only in a stat card.

4.5 No daily log / behavior journal
Caregivers need a low-effort "how was today?" log. Today there's nothing.

4.6 No home-strategy recommendations
The Brain clone generates accommodations. Parents see them. Caregivers should see an age-appropriate, home-context distilled version: "Today, Ada benefits from a 10-minute movement break before homework." This surface doesn't exist.
