Prompt 2.1 — Make CI Lint & TypeCheck Blocking
Code
.github/workflows/ci.yml lines 37 and 41 set continue-on-error: true on both
pnpm lint and pnpm build (type-check). Lines 114, 191, 197, 204 repeat this
pattern for security scans. This means type errors, lint violations, and even critical
security findings do not block pull request merges.

File to change: .github/workflows/ci.yml

Task:
1. Remove continue-on-error: true from the Lint step (line 37).
2. Remove continue-on-error: true from the Type check step (line 41).
3. For the security scan steps (lines 114, 191, 197, 204), keep
   continue-on-error: true but add a summary step at the end of the job that
   checks exit codes and posts a PR comment with findings.
4. Add a job-level if: always() on a new ci-summary job that collects and reports
   the status of all upstream jobs.

Acceptance criteria:
- A PR with a TypeScript error fails CI.
- A PR with an ESLint error fails CI.
- Security scan findings appear in PR comments but do not block merge.
- Existing passing PRs remain green.

accommodations, use wrong language level, or miss IEP goals. Zero tests exist.

1. Test build_system_prompt() for each functioning level (STANDARD through PRE_SYMBOLIC):
   - STANDARD → contains "Socratic method", no picture-based instructions.
   - NON_VERBAL → contains "partner-assisted", "icons only", AAC references.
   - PRE_SYMBOLIC → contains "parent coaching mode".
2. Test accommodation injection: when active_accommodations includes "text_to_speech",
   the prompt includes relevant instructions.
3. Test IEP goal injection: when iep_profile.goals has entries, they appear in prompt.
4. Test sensory profile injection: hyper-visual → prompt includes "muted colors,
   minimal animations".
5. Test curriculum alignment: when curriculum_alignment.framework is "CCSS", the prompt
   references Common Core.

Acceptance criteria:
- ≥25 test cases.
- pytest services/ai-svc/tests/test_prompt_builder.py -v → all pass.
