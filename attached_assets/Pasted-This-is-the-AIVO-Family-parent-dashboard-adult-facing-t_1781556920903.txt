# AIVO Parent Dashboard Design Constitution (prepend to every prompt below)

You are designing/building AIVO's **parent ("AIVO Family") dashboard** in `apps/web-v2` (Next 15,
Tailwind v4, Radix, `@aivo/brand` + `@aivo/ui`). Audience: **a parent/caregiver** — an adult,
often anxious, managing a neurodiverse child's learning. This is the calm, clear, trustworthy adult
register of the AIVO brand (NOT a learner surface).

Design language (match the reference mockup):
- **Family register tokens** — formalize a "Family" accent (the teal/green + violet-insight pairing
  in the mockup) as `@aivo/brand` role-theme tokens; do NOT hardcode teal. Violet stays the brand
  spine; the cloud host mascot appears in an adult, encouraging tone. No raw hex (ESLint enforces).
- **Card-based, scannable, low-anxiety** — generous spacing, rounded cards, one clear "what to do
  next," progress shown warmly (rings, sparklines), supportive microcopy ("You're doing great").
- **Type/a11y:** Satoshi/Inter + Atkinson Hyperlegible option; WCAG **2.2 AA** (this is a B2C +
  school-procurement surface), full keyboard, visible focus, semantic landmarks, RTL + 10 locales.

Two hard rules:
1. **Truthful data only.** Every number (streak, sessions, time-on-task, "18% improved", mastery)
   must trace to a real service/DB value, or render an honest empty/loading state. No hardcoded
   mockups (the current `snapshot` page and unwritten XP/streak — audit GAP-6 — are the anti-pattern
   to eliminate). No fabricated outcome stats.
2. **Access control.** Every learner-scoped view enforces `parentCanAccessLearner`; never leak one
   learner's data to another guardian. Compliance footer uses approved hedged wording linking real
   pages (Privacy, Security, Accessibility, COPPA, FERPA).

Shared chrome: `AppShell` + `PARENT_NAV` left rail (Home, Progress, Sessions, Goals (IEP), Messages,
Reports, Calendar, Resources, Settings), header greeting + notifications + account menu, encouragement
rail, compliance footer.

For each page: don't jump to code. First return (a) the data contract (every value → its source or
empty state), (b) the layout/state map (loading/empty/error/multi-learner), (c) the visual direction
in tokens. Pause for approval.
