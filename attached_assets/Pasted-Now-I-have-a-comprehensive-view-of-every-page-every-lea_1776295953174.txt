## 1. Executive Summary

### 1.1 Purpose

This PRD defines the complete redesign of the AIVO Parent Dashboard — the **most emotionally critical interface** in the entire platform. Parents of children with autism, learning disabilities, and other neurodivergences arrive at AIVO in a state of vulnerability: exhausted from advocating, overwhelmed by data, and desperately seeking clarity about their child's progress.

The parent dashboard must be:
- 🫶 **Emotionally intelligent** — warmth-first design that reduces anxiety, celebrates growth, and never overwhelms
- 🧠 **Cognitively accessible** — parents themselves may be neurodivergent; the UI must work for everyone
- 📊 **Clarity over complexity** — translate AI/brain data into plain-language insights a grandparent could understand
- 📱 **Mobile-first** — most parents access AIVO on phones during school pickup, therapy waiting rooms, or late at night
- 🔒 **Trust-building** — COPPA-compliant, transparent about what data exists and how AI decisions are made

## 2. Design Philosophy

### 2.1 The "Warm Clarity" Principle

Every screen the parent sees must answer three questions immediately:
1. **How is my child doing?** (the emotional need)
2. **What should I do next?** (the action need)
3. **Is everything okay?** (the reassurance need)

### 2.2 Emotional Design Guidelines

| Emotion | Design Response | Implementation |
|---|---|---|
| **Anxiety** ("Is my child falling behind?") | Lead with growth, never deficits. Show "improved by 12%" before "at 45% mastery" | Green-first color coding; growth arrows before absolute numbers |
| **Overwhelm** ("There's so much data") | Progressive disclosure. Summary first, detail on tap | Collapsible cards, "Learn More" expandable sections |
| **Hope** ("Is this working?") | Celebrate every win. Micro-milestones, streaks, XP celebrations | Confetti on milestones, warm toast notifications, "Weekly Win" feature |
| **Frustration** ("I don't understand this brain thing") | Plain language. No jargon. Tooltip explanations on every technical term | Hover/tap tooltips, "What does this mean?" links, XAI explanations |
| **Guilt** ("I haven't logged in in 2 weeks") | No guilt messaging. Welcome back warmly. Show what was accomplished while away | "While you were away, [Child] completed 5 sessions and earned 230 XP!" |
| **Pride** ("My child did something amazing") | Shareable moments. Progress snapshots. "Brag Board" | Download/share progress summary cards for social or IEP meetings |

### 2.3 Neurodiversity-First Interface Design

Parents of neurodiverse children are themselves often neurodivergent (ADHD, autism, dyslexia have strong hereditary components). The dashboard MUST accommodate:

| Need | Implementation |
|---|---|
| **ADHD (attention regulation)** | Clear visual hierarchy, immediate feedback, minimal distractors, completion indicators, no walls of text |
| **Autism (predictability)** | Consistent patterns, predictable navigation, no surprise modals, routines honored |
| **Dyslexia (reading ease)** | Minimum 16px body text, sans-serif fonts, adequate line spacing (1.5x), left-aligned text, no justified text |
| **Anxiety (cognitive load)** | Maximum 3 actions per view, clear "safe" exits, never trap users in flows |
| **Executive function (planning)** | Visual timelines, step indicators, "what's next" prompts, calendar integration |
| **Sensory sensitivity** | Respect `prefers-reduced-motion`, `prefers-color-scheme`, `prefers-contrast`; no auto-playing media, no flashing |

## 3. User Personas

### 3.1 Primary: The Advocate Parent (80% of users)

- **Who:** Parent of a child with autism, ADHD, learning disability, or developmental delay. Aged 28–50.
- **Context:** Manages IEP meetings, therapy appointments, school communications. Constantly advocating for their child.
- **Emotional state:** Exhausted but determined. Needs tools that reduce their burden, not add to it.
- **Tech skill:** Moderate. Uses iPhone, occasionally laptop. Comfortable with apps, not dashboards.
- **Access pattern:** 5–10 minute sessions, usually on phone. Checks at morning (before school), evening (reviewing day), and weekend (planning).
- **Top questions:** "How did my child do today?" / "Is the tutoring actually working?" / "What do I show at the IEP meeting?"

### 3.2 Secondary: The Multi-Child Parent

- **Who:** Parent managing 2–4 children on the platform, possibly with different support needs.
- **Key need:** Quick switching between children. At-a-glance comparison. Unified notifications.
- **Pain point:** Current dashboard requires scrolling through all children; no quick-switch.

### 3.3 Tertiary: The Co-Parenting Family

- **Who:** Separated/divorced parents sharing AIVO access. Or grandparent as primary caregiver.
- **Key need:** Both parents see same data. Activity log shows who did what. No conflicting settings.
- **Pain point:** Currently only one parent account per learner.

### 3.4 Quaternary: The First-Time-Tech Parent

- **Who:** Parent who isn't tech-savvy. Possibly elderly grandparent as caregiver.
- **Key need:** Extremely simple interface. Big buttons. No hidden menus. Step-by-step guidance.
- **Pain point:** 12-card navigation grid is overwhelming. Technical terms (functioning level, brain state) are confusing.

| Requirement | Standard |
|---|---|
| WCAG 2.1 AA compliance | All parent pages |
| Color contrast | 4.5:1 text, 3:1 UI components — with AAA option via high contrast setting |
| Touch targets | Minimum 44×44px (WCAG 2.5.5) |

| Font scaling | UI remains functional up to 200% browser zoom |
| Text spacing | Support WCAG 1.4.12 text spacing overrides without breaking layout |

| Requirement | Implementation |

## 9. Testing Strategy

### 9.1 Critical User Flows to E2E Test

| Flow | Steps | Acceptance |
|---|---|---|
| First-time parent journey | Register → Add child → Complete assessment → Brain created → First session | End-to-end works without dead ends |
| Settings persistence | Toggle accommodation → Refresh page → Verify toggle state persists | Settings saved to API and restored |
| Inbox workflow | Recommendation arrives → Parent opens inbox → Reviews → Approves → Item moves to archive | Full approval workflow |
| Multi-child switching | Parent has 2 children → Switches between them → Data is correct per child | No data bleed between children |
| Progress report download | Open progress page → Select date range → Download PDF → Verify contents | PDF generates with correct data |
| Milestone celebration | Child completes milestone → Parent sees it on home dashboard → Shares card | Full celebration flow |

### 9.2 Accessibility Testing

| Layer | Tool | Coverage |
|---|---|---|
| Automated scan | axe-core via Playwright | Every page route |
| Color contrast | axe-core + manual spot-check | All text, all states (hover, active, disabled) |
| Screen reader | Manual VoiceOver (Mac) + NVDA (Windows) | Critical flows: home, inbox, progress, settings |
| Keyboard only | Manual testing | Complete flows without mouse |
| Reduced motion | `prefers-reduced-motion: reduce` in Playwright | All pages — no animation occurs |
| Zoom 200% | Manual browser zoom test | Layout remains functional, no overflow |

### 9.3 Emotional UX Testing

| Test | Method | Metric |
|---|---|---|
| "First impression" | Show parent dashboard to 5 parents of neurodiverse children | Qualitative feedback on warmth, clarity, anxiety reduction |
| "Find your child's progress" | Task-based usability test | Time to find mastery score (target: < 15 seconds) |
| "What should I do?" | Parent asked "what does AIVO want you to do?" | Parent can identify next action without prompting |
| "IEP meeting prep" | Parent generates progress report | Time to download PDF (target: < 30 seconds) |

## 10. Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Parents confused by layout change (redesign anxiety) | Medium | Medium | Opt-in "Try new dashboard" toggle for 2 weeks; fallback to old |
| Milestone/badge system feels patronizing | Low | Medium | User testing with parents; make celebrations toggleable |
| Progress report data inaccuracy | Medium | High | Cross-reference gradebook data with session data; show data freshness timestamps |
| Settings migration (from lost client-side to persisted) | Low | Low | Default values for all settings; no data to migrate since it was never saved |
| Mobile bottom tab bar interferes with iOS safe area | Medium | Medium | Use `env(safe-area-inset-bottom)` padding |
| Inbox notification overload | Medium | Medium | Smart grouping (combine 5 mastery milestones into "Alex had a great week!"); configurable frequency |
| Shareable cards contain PII | Low | High | Only include first name; no school, grade, diagnosis, or FL in shareable output |
| PDF generation slow for large data sets | Medium | Medium | Async generation with progress indicator; cache generated reports for 24h |
