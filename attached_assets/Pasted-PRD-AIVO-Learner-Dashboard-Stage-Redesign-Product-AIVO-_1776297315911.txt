PRD: AIVO Learner Dashboard & Stage Redesign
Product: AIVO AI Learning Platform v3
Surface(s): /dashboard/learner, The Stage (components/stage/*), Discovery Adventure (components/discovery/*)
Owner: Learner Experience Pod
Author: Product / Design / Engineering
Status: Draft v1.0
Date: April 15, 2026

1. Executive Summary
AIVO serves neurodiverse learners spanning five functioning levels (STANDARD → SUPPORTED → LOW_VERBAL → NON_VERBAL → PRE_SYMBOLIC). Today, three core learner surfaces ship to production:

Learner Dashboard (apps/web/src/app/dashboard/learner/page.tsx, 491 lines) — a single-file gamified hub with XP/level/streak/coins, daily missions, SEL check-in, and a 4-tutor grid.
The Stage (apps/web/src/components/stage/*) — a full-screen immersive lesson surface with beat-based session flow, per-tutor themes, sensory adaptations.
Discovery Adventure (apps/web/src/components/discovery/*) — an immersive 6-chapter baseline assessment (replacing a traditional quiz).
These surfaces work, but user research, accessibility audits, and parent/therapist feedback consistently surface the same issues: visual density, unpredictable navigation, inconsistent affordances across functioning levels, cognitive overload from simultaneous gamification + lesson surfaces, and lack of clear "what should I do next" wayfinding. The dashboard also does not yet feel like a place a child wants to return to.

This PRD defines a 6-sprint redesign to turn the learner surfaces into a cohesive, neurodiverse-first, engaging, and WCAG 2.1 AA+ by default learner experience — without regressing on the 14 tutors, 5 functioning levels, engagement system, or the existing API contract.

2. Goals & Non-Goals
2.1 Goals
G1. Deliver a learner dashboard that a neurodiverse child wants to return to daily (measurable via 7-day returning-learner rate ≥ 65%).
G2. Reduce cognitive load: ≤ 1 primary action visible above the fold ("What's next"), ≤ 5 secondary choices.
G3. Make all learner surfaces functioning-level adaptive by construction, not by conditional isLow branches sprinkled through a 491-line file.
G4. Make "The Stage" and the Discovery Adventure predictable, skippable, interruptible, and pause-safe for learners with sensory or executive-function challenges.
G5. Ship a shared @aivo/learner-ui component kit that enforces accessibility tokens (contrast, hit targets, motion, focus) at the design-token level.
G6. Achieve zero axe-core violations across all learner routes, 100% keyboard reachable, fully screen-reader narratable.
2.2 Non-Goals
Redesigning the Parent/Teacher/Caregiver/Therapist/Admin dashboards (tracked separately).
Changing tutor personalities, prompts, LLM routing, or the Brain Clone pipeline.
Redesigning the gamification economy (XP/coins/gems math, quest structure).
Mobile app parity (mobile redesign follows web in a later phase, but tokens are shared-ready).
2.3 Success Metrics
Metric	Baseline	Target (end of Sprint 6)
Axe-core violations on learner routes	3–7 per route	0
7-day returning learner rate	~48%	≥ 65%
Avg. time to start first lesson of day	~45s	< 15s
Baseline assessment completion rate	~72%	≥ 88%
Lesson abandonment (Stage quit mid-beat)	~18%	≤ 8%
Parent-reported "my child can navigate independently" (survey)	61%	≥ 85%
Keyboard-only task completion (home → lesson → complete)	partial	100%
Lighthouse a11y score	92	100
3. Target Users & Neurodiversity Personas
We design for six representative learners; every feature must be traced to at least one.

Persona	Functioning Level	Key Needs
Ada, 9, ADHD + dyslexia	STANDARD	Short sessions, visual anchors, dyslexia-safe font, clear "next"
Bram, 11, Autism Level 1, sensory sensitivity	SUPPORTED	Predictable layouts, reduced motion, low saturation, subtitles, preview of what's coming
Cass, 7, Autism + anxiety	SUPPORTED	Pause/break anywhere, "safe room" escape, emoji mood check
Dev, 10, apraxia, minimally verbal	LOW_VERBAL	Icons > text, AAC-friendly tap targets, voice-optional
Ellis, 8, nonverbal autism	NON_VERBAL	Picture-first, no timers, generous tap zones, sensory profile honored
Finn, 6, pre-symbolic	PRE_SYMBOLIC	Parent co-pilot, cause/effect only, no reading required
Core neurodiversity design tenets (apply everywhere):

Predictability — layouts never reflow on state change; incoming content fades into a fixed slot.
Preview — every transition has a "you're about to go to X" preview ≥ 600ms (configurable).
Pause anywhere — global "Take a break" cloud button on every learner surface; resumes exactly where left.
One primary, no surprises — exactly one CTA is dominant at any moment; secondary actions muted.
Choice without penalty — skipping, re-watching, and slowing down must be first-class, not hidden.
Sensory honesty — motion, sound, saturation, particle count all read from learner sensory profile; no per-component overrides.
Words are optional — every text label pairs with an icon + audio (TTS) + optional sign/symbol.
Time is optional — no countdowns on skill checks unless explicitly gamified and dismissible.
4. Current State Analysis
4.1 Learner Dashboard (apps/web/src/app/dashboard/learner/page.tsx)
What works

Clear gamification surface (XP / streak / badges / currency).
SkipLink + main-content focus target already present (line 222, 243).
Functioning-level awareness via isLowFunctioning() helper (line 44).
SEL check-in with emoji selector and guided breathing exercise (line 33–40).
Baseline gate — learner is routed to Discovery if not yet completed (line 73).
Pain points

Single 491-line file with 12+ useStates and a 160-line JSX return → hard to test, hard to adapt per persona.
"isLow" branches (lines 200, 247, 276, 304, 344, 369, 382) duplicate markup — inconsistent styling drift.
Simultaneous surfaces above the fold: stats grid + pill nav + daily missions + tutor grid + celebration overlay → cognitively crowded for SUPPORTED/LOW_VERBAL.
Only 4 tutors shown (line 202 slice(0,4)) — learners with subscriptions to 5+ tutors can't reach them from the home.
"What should I do next?" is implicit — no recommended next action from the Brain.
Celebration overlay is a 🌟 bounce — not themed, not tutor-aware, not dismissible.
No wayfinding breadcrumb or "home" anchor; the top-right Log out is the most prominent persistent control.
Pill nav row uses 5 different pastel hues — fails cohesive focus hierarchy and is noisy for visual-sensitive learners.
4.2 The Stage (apps/web/src/components/stage/StageLayout.tsx, 169 lines)
What works

Beat-based session flow (useSessionFlow) is a strong architectural bet.
Sensory adaptations are applied at the layout root via filter: saturate(...) (line 42).
Reduced-motion particle count (5 vs 15, line 121).
Per-tutor theme system with env names, accent, gradient (line 35).
role="application" + aria-label on the shell (line 44).
Pain points

role="application" on the outer shell is aggressive — screen readers treat the entire Stage as a custom widget and suppress normal reading mode. Should be scoped to the response zone only.
The pause button is an emoji ☁️ with aria-label="Pause / Take a break" — great affordance for verbal learners, but no visible text label for learners who need redundant coding. LOW_VERBAL personas miss it.
Header uses bg-black/20 backdrop-blur-sm — contrast fails WCAG AA on certain tutor gradients (Harmony, Muse).
No "I need help" / "I need a break now" escape separate from Pause — blurs two distinct affordances.
ProgressPath is purely linear — no sense of "how many beats until break" which is the question learners actually ask.
Subtitles are gated on adaptations.useSubtitles — they should be on by default and togglable, not opt-in buried in profile.
Background particle system spawns 15 animated emoji — for SUPPORTED personas with anxiety this is an unacceptable default even with motionReduced at 5.
No "preview card" before content appears — beats pop into the StageContent slot, violating the predictability tenet.
4.3 Discovery Adventure / Baseline Assessment (components/discovery/*)
What works

6 themed chapters with tutor characters — strong narrative frame.
Adaptive difficulty engine (useDiscoveryEngine.ts).
Break activity (BreakActivity.tsx) between chapters (30–45s music/word/move).
PreAdventure tutor introduction with staggered reveal (PreAdventure.tsx, 88 lines).
Functioning-level-aware chapter counts (STANDARD=6 → NON_VERBAL=3 → PRE_SYMBOLIC=0).
Pain points

PreAdventure auto-advances on timers (line 19: setTimeout(..., 800 + idx * 900)). Learners cannot slow the reveal or replay it. Anxiety personas (Cass) report "feeling rushed before it even started."
"Let's Go! 🚀" is the only exit — no "meet the friends" secondary path where the learner can tap a tutor and hear them again.
Dark purple gradient (from-indigo-950 via-purple-950) may overstimulate learners with photosensitivity concerns; no light variant.
No "adventure map" preview on first load — learners don't know how many chapters they'll face. The AdventureMap component exists but is shown between chapters, not upfront.
Break activity is skippable but defaults to 30–45s — no way for an overwhelmed learner to extend it.
Finale / Awakening sequence runs 25s (STANDARD) — long, not pause-safe mid-sequence, can't be exited without losing the assessment result.
No "I'd rather have my parent with me" affordance at start of assessment for PRE_SYMBOLIC/NON_VERBAL.
Questions are delivered inside an immersive fullscreen layout; a learner who gets stuck has no route back to the dashboard without aborting.
5. Design Principles & Guardrails
Composition over conditionals. Replace isLow branching with a <LearnerSurface variant={flProfile}> pattern driven by a functioning-level profile object ({ density, maxChoices, textWeight, motionBudget, audioFirst }).
One slot, many fills. Every surface has exactly one "primary slot" that the Brain populates with the recommended next action (lesson, break, or check-in).
Motion budget. Every surface has a total "motion budget" in concurrent animated elements. STANDARD = 8, SUPPORTED = 4, LOW_VERBAL = 2, NON_VERBAL = 1, PRE_SYMBOLIC = 0 (static).
48×48 minimum hit target (WCAG 2.5.5), 72×72 preferred on LOW_VERBAL+.
Dual-encode everything. Color + icon + text + audio. Never rely on one channel alone.
Autosave everything. Any interruption (network, pause, parent call) resumes mid-beat.
Respect the sensory profile at the token layer. Color saturation, font size, line-height, letter-spacing, and animation durations are CSS custom properties the sensory adapter writes to document.documentElement.
No dead ends. Every screen has a visible "home" and a visible "break" affordance.

7.4 The Stage (redesigned)
Outer shell: role="main" with named region; role="application" scoped to ResponseZone only.
New BeatPreview overlay: before each beat, a 600–1200 ms card slides in announcing "Next: [beat title] — [icon]" with a visible "I'm ready" button (auto-advances if motion budget > 0 and user hasn't interacted in 2s).
Break Cloud: persistent ☁️ Break with visible text label (not only aria-label). Tapping opens BreakCloud overlay — choose breathing, music, stretch, or "just sit". Lesson paused; resume button always visible.
Help button: separate from Break — says "I need help" — calls the current tutor to re-explain in simpler language.
Progress: "3 / 8 beats until a break" (not just a bar). Break is a first-class checkpoint on the path.
Subtitles ON by default — can be disabled in profile but default is accessible.
Background particles: count drops to (STANDARD=10, SUPPORTED=3, LOW_VERBAL=0, NON_VERBAL=0, PRE_SYMBOLIC=0). No emoji-spam defaults.
Header: tutor name + env + accent become a clean header band with enforced --learner-saturation cap and per-tutor safe contrast token (tested at build time in §9).
Co-viewing indicator (parent watching) becomes a visible friendly badge: "Your grown-up is watching too ❤️" (opt-out per learner).
Exit: always visible "Back home" alongside Pause — no dead ends.
7.5 Discovery Adventure (redesigned baseline)
PreAdventure v2: tutor reveals are click-to-advance by default, not timer-based. Each tutor card is tappable to re-hear the intro line. A visible "Show me the map first" secondary button routes to a static AdventureMap preview (learner sees all 6 stops, grays out stops they'll visit after breaks).
Light and Dark variants (learner's sensory profile picks). Dark = current gradient. Light = cream #FFF8EB → soft lavender #E9E0FF with charcoal text.
Adventure Map: before Chapter 1, learner sees the whole journey with stop icons. This is already built — promote to entry screen.
Chapter entry: show a "Ready?" card with three buttons: Start, Hear it again, Bring my grown-up. The third triggers a parent-pair flow for learners under 8 or flagged anxious.
Break Activity: min duration removed. Learner decides when to continue. Parent can set "at least 60s" from settings.
Exit to home: during any chapter, "Take a break" → "End for now, keep my progress" is permitted. Returning to dashboard resumes exactly where the learner left.
Finale / Awakening: add mid-sequence "I want to stop watching" button. Auto-save at every phase transition so the Brain-Clone pipeline still runs on the results collected so far.
No-text path: for NON_VERBAL/PRE_SYMBOLIC, text-free version where every prompt is picture + sign + audio.
8. Accessibility Requirements (Hard Gates)
Every PR touching learner surfaces must satisfy these or be blocked by CI:

Axe-core clean on all learner routes (/dashboard/learner, /dashboard/learner/stage/*, /dashboard/learner/assessment, shop, quests, homework, challenges, leaderboard, badges, profile, settings, tutors).
Keyboard flow test: Playwright script that completes home → start lesson → answer beat → pause → resume → celebrate → home using Tab/Enter/Space/Esc only. Added to CI alongside existing .github/workflows/a11y-tests.yml.
Screen reader snapshots: aria-snapshot Playwright fixtures for home, stage, assessment. Locked-in and reviewed on change.
Contrast oracle: build-time script that loads every tutor theme gradient + text color combo through a WCAG ratio function. Failing combos fail the build.
Reduced motion: every motion rule must reference var(--learner-motion-ms) or be inside a @media (prefers-reduced-motion: reduce) block.
Focus visible: 3px ring in tutor accent color, 3px offset, never removed.
No emoji-only buttons: lint rule (custom ESLint plugin) that blocks <button> containing only an emoji string without sibling text or aria-label that matches a visible label.
Touch targets: computed style test asserting all interactive elements meet --learner-hit-target.
Dyslexia font option: OpenDyslexic as opt-in alternative; default remains Fredoka/Nunito with enforced letter-spacing from sensory vars.
Captions + audio descriptions on any motion video/animation > 3s in duration.

Sensory profile not yet set at first login	High	Medium	Default to "SUPPORTED" profile as safest median until parent completes sensory onboarding.
Tutor gradient contrast failures cascade	Medium	High	Contrast oracle at build; "safe overlay" token band added behind text when gradient fails.
Motion-budget changes reduce perceived delight	Medium	Medium	Per-learner parent toggle for "extra sparkles" that respects reduced-motion at OS level.
Baseline resume-from-exit corrupts brain clone input	Low	High	Autosave at every answer; clone pipeline already accepts partial domains. Add tests.
Legacy isLow branches regress during refactor	Medium	Medium	Variant snapshot tests in Storybook; Playwright matrix per FL.
i18n drift across 10 locales	Medium	Low	Require string parity in CI (already enforced via existing i18n checks).
Feature flag stranding old users	Low	Medium	2-week migration window; telemetry on flag-off cohort.
