# Enterprise Admin Hardening — Sprint-by-Sprint Prompts

> Target repo: `artpromedia/aivo-ai-learning`
> Scope: Super Admin (`PLATFORM_ADMIN`) and District Admin (`DISTRICT_ADMIN`) consoles + supporting services (`identity-svc`, `admin-svc`, `packages/db`, `packages/security`, `apps/web`).
> Each sprint is a **self-contained prompt** that can be pasted into a coding agent. Prompts assume no prior context.
> Reference audit findings are tagged inline (A1, B1, C3, …) and map to `docs/audits/admin-enterprise-audit.md`.

### Prompt 1.2 — Edge Middleware for Admin/District Routes
```

2. For request paths matching `/dashboard/admin/**` OR `/admin/**`:
   - If no `refreshToken` cookie, 302 → `/admin/login?returnTo=<path>`.

     `auth-provider`) — if absent, fall through to client redirect.
3. For `/dashboard/district/**` OR `/district/**`:
   - Redirect to `/district/login` if unauthenticated.

     admin console   → admin.aivolearning.com + localhost

5. Add unit tests using `next/experimental/testmode` for middleware.
6. Update `infra/k8s/overlays/hetzner/web-ingress.yaml` to add a
   ModSecurity annotation blocking non-allowlisted hosts at the edge as defense-in-depth.

Ship behind no flag — this is pure redirect hardening.
```

## Sprint 2 — Phishing-Resistant MFA (1.5 weeks) · Findings B1, B2, B6, B7, B9

### Prompt 2.1 — TOTP Authenticator App Support
```
Extend MFA from email-only to email + TOTP.

1. In `packages/db/src/schema/users.ts`:
   - Widen `mfaMethod` enum to `'email' | 'totp' | 'webauthn'`.
   - Add `mfaSecret TEXT` (nullable, stores encrypted TOTP seed).
   - Add migration in `packages/db/drizzle/`.

2. Add `packages/security/src/totp.ts` using `otpauth` (npm). Functions:
   - `generateTotpSecret()` → { secret, otpauthUrl }
   - `verifyTotp(secret, code, window=1)`
   - Encrypt/decrypt secret with `MFA_ENCRYPTION_KEY` (already provisioned in
     HETZNER_DEPLOYMENT_GUIDE.md but unused — wire it up; fail hard in prod if missing).

3. New routes in `services/identity-svc/src/routes/auth.ts`:
   - `POST /api/auth/mfa/totp/enroll` → returns otpauthUrl + QR dataURI
   - `POST /api/auth/mfa/totp/confirm` { code } → activates TOTP, disables email fallback
   - `POST /api/auth/verify-mfa` → accept TOTP code when user.mfaMethod='totp'

4. UI in `apps/web/src/components/settings/MfaSettings.tsx`: add
   "Use an authenticator app" tab with QR code render (`qrcode.react`).
   Forced-MFA roles must switch to TOTP within 30 days (soft warning for now).

5. Rate-limit: 5 failed TOTP codes in 10 min locks the user — use the existing
   `mfa_codes.attempts` column or a new `mfa_lockouts` table.

Tests: unit (TOTP verify), integration (full enroll → login flow), Playwright
(admin enables TOTP and logs in with it).
```

### Prompt 2.2 — WebAuthn / Passkeys for PLATFORM_ADMIN
```
Add passkey (WebAuthn L2) support, marked as the PREFERRED method for
PLATFORM_ADMIN per NIST 800-63 AAL3.

1. Use `@simplewebauthn/server` on identity-svc, `@simplewebauthn/browser` on web.
2. New table `webauthn_credentials` (userId, credentialId, publicKey, counter,
   transports, deviceName, createdAt, lastUsedAt).
3. Routes:
   - POST /api/auth/webauthn/register/options
   - POST /api/auth/webauthn/register/verify
   - POST /api/auth/webauthn/login/options
   - POST /api/auth/webauthn/login/verify
4. On login, if user has a registered credential, prefer WebAuthn over OTP.
   Email OTP becomes the fallback only if no passkey is present.
5. Settings UI: list registered passkeys, rename, revoke.
6. Gate behind `ADMIN_ENTERPRISE.STRONG_MFA`.

RP ID: set to `aivolearning.com` in prod; `localhost` in dev. Document in
`docs/security-architecture.md` §1.2.
```

### Prompt 2.3 — Backup / Recovery Codes
```
Generate 10 single-use recovery codes at MFA enrollment.

1. Table `mfa_recovery_codes` (id, userId, codeHash, usedAt, createdAt).
2. Hash with argon2id at rest — never store plaintext.
3. UI: one-time download as .txt and print view after enrollment; show count
   of remaining codes in settings with a "regenerate" action (invalidates old).
4. `/api/auth/verify-mfa` accepts a 10-char recovery code if the user cannot
   access their primary factor. Each consumes one code and triggers an email
   alert to the admin.
5. Audit-log every recovery-code use as action `MFA_RECOVERY_USED`.
```

### Prompt 2.4 — Hash Stored OTP Codes (B7)
```
Refactor `services/identity-svc/src/services/mfa.ts`:
- Store `mfa_codes.code` as SHA-256 (or argon2id for defense-in-depth, but SHA-256
  is acceptable given 10-minute TTL) rather than plaintext.
- `verifyMFACode()` compares hashes.
- Add migration + backfill script (truncate existing unused codes is acceptable
  since TTL is 10 min).
Run the existing test suite and add a regression test asserting the DB column
never contains a plaintext 6-digit string.

## Sprint 3 — Step-Up Authentication for Sensitive Ops (1 week) · Finding B3

### Prompt 3.1 — Step-Up Token Flow
```
Today `/dashboard/admin/compliance` claims "Step-Up Authentication" = true.
Make this real.

1. Add `packages/security/src/stepUp.ts`:
   - `issueStepUpChallenge(userId, scope)` → stores a pending challenge
     (scope examples: "tenant:delete", "user:impersonate", "brain:reset",
      "data:export", "role:change").
   - `verifyStepUp(userId, scope, code)` → consumes challenge, returns a
     short-lived (5-min) `stepUpToken` JWT with `{ sub, scope, jti }`.

2. Backend enforcement: create a Fastify preHandler `requireStepUp(scope)` that
   verifies the `x-step-up-token` header against the route's scope. Apply to:
     POST /api/admin/impersonate                       → scope "user:impersonate"
     DELETE /api/admin/users/:id                       → scope "user:delete"
     PUT  /api/admin/users/:id (when role changes)     → scope "role:change"
     PUT  /api/admin/tenants/:id (status=suspended)    → scope "tenant:suspend"
     DELETE /api/admin/tenants/:id                     → scope "tenant:delete"
     POST /api/admin/learners/:id/reset-brain          → scope "brain:reset"
     GET  /api/research/export/anonymized              → scope "data:export"
     PUT  /api/admin-svc/config                        → scope "config:update"

3. UI: create `apps/web/src/components/admin/StepUpModal.tsx` that intercepts
   destructive actions. Modal challenges for the user's strongest enrolled
   factor (passkey → TOTP → email). On success, adds the returned token to the
   next request.

4. Update `/dashboard/admin/compliance/page.tsx` so the "Step-Up Auth" badge
   is driven by a runtime probe (GET /api/admin-svc/compliance/controls) that
   returns real status.

5. Tests: e2e covers "admin tries to delete tenant → modal → wrong code → retry →
   correct code → deletion succeeds, audit log contains STEP_UP_VERIFIED + TENANT_DELETED".
```

### Prompt 3.2 — Runtime Compliance Probes
```
Replace the hardcoded boolean array in `apps/web/src/app/dashboard/admin/compliance/page.tsx`
with `GET /api/admin-svc/compliance/controls`. The endpoint returns each control's:
  - id, label, category, status ("pass"|"warn"|"fail")
  - evidenceUrl (link to log/dashboard proving it)
  - lastCheckedAt

Controls to probe at runtime (not hardcoded):
  - JWT RS256 signing (inspect `packages/security` loaded keys)
  - MFA adoption rate (count users with mfaEnabled / INTERNAL_ROLES)
  - Step-Up enforcement (reflect ADMIN_ENTERPRISE.STEP_UP_AUTH flag + route count that uses requireStepUp)
  - Tenant isolation (count of 403s on mismatched tenant in last 24h)
  - HTTPS (probe ingress on startup)
  - AES-256 at rest (probe Postgres `pg_settings` for `ssl` + check disk encryption flag file)
  - Audit immutability (check DB privilege for `admin_audit_log`)
  - Rate limiting (reflect @fastify/rate-limit registration)
  - Secret scanning (check gitleaks CI status via GitHub API, cached hourly)

If a probe fails, render the card red with a link to the runbook.
```

## Sprint 4 — Audit Immutability + Impersonation Logging (4 days) · Findings C2, C3, C6

### Prompt 4.1 — Append-Only Audit Log
```
Make `admin_audit_log` and `district_activity_log` append-only at the DB layer.

1. Add a Drizzle migration that:
   - Creates a Postgres role `aivo_audit_writer`.
   - GRANTS INSERT, SELECT on both tables to `aivo_audit_writer`.
   - REVOKES UPDATE, DELETE, TRUNCATE from `aivo_app` (the runtime role).
   - Adds a `BEFORE UPDATE OR DELETE` trigger that RAISES EXCEPTION.

2. Add a scheduled cryptographic chain: each new row computes
   `prevHash = previous row's hash`, `hash = sha256(prevHash || row_payload)`.
   Expose `GET /api/admin-svc/audit-log/verify` that walks the chain and
   returns `{ valid: true, verifiedUpTo: <id> }`.

3. Document the restoration runbook in `docs/runbooks/audit-restore.md`
   (because true append-only means a bad INSERT can't be rolled back).

4. Tests: attempt UPDATE/DELETE via aivo_app connection → expect 42501 error.
```

### Prompt 4.2 — Full Impersonation Audit Trail
```
Today `POST /api/admin/impersonate` in services/identity-svc/src/routes/admin.ts
returns an impersonation JWT but logs nothing.

1. Call `logAuditEvent()` for action `IMPERSONATION_STARTED` with:
   { adminId, adminEmail, targetUserId, targetRole, targetTenantId, ip, ua }

2. Add `POST /api/admin/impersonate/end` → logs `IMPERSONATION_ENDED`
   with duration. The `auth-provider.exitImpersonation()` method must call it.

3. Middleware: on any request where the JWT has `impersonatedBy`, inject both
   actor IDs into every subsequent audit log entry (`actorId` = real admin,
   `onBehalfOfId` = impersonated user). Add a nullable `on_behalf_of_id` UUID
   column to `admin_audit_log`.

4. UI: `/dashboard/admin/compliance/audit-log` renders impersonation entries
   with a distinct orange badge and shows both identities.

5. IP allowlisting (C6): new env `ADMIN_IP_ALLOWLIST` (CIDR list, empty=off).
   Enforce in a Fastify `onRequest` hook on `/api/admin/**` and `/api/admin-svc/**`.

## Sprint 5 — Session Hygiene (3 days) · Findings B4, B5, B10

```

   deviceFingerprint).

2. For roles in INTERNAL_ROLES:
   - Refresh token TTL shortened from 30d → 12h.
   - Inactivity timeout: configurable via ADMIN_ENTERPRISE.ADMIN_SESSION_IDLE
     (default 240 min). `POST /api/auth/refresh` rejects with 401 if
     `now - lastActivityAt > idleMin`.

   `PUT /api/auth/session/heartbeat`. If idle > 5min before timeout, show a
   warning modal.

4. Device fingerprint: hash (UA + Accept-Language + sec-ch-ua) at login and
   on subsequent refreshes. Mismatch → force re-MFA.

5. Tests: simulate 241-minute idle → refresh rejected; pass → granted.
```
