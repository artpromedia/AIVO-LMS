## 1. Executive Summary

The **AIVO Platform Admin Dashboard** is an enterprise-ready, centralized management console that provides full operational control over the entire AIVO ecosystem — spanning AI/ML services, learning applications, mobile apps, billing, compliance, multi-tenant school/district management, and infrastructure monitoring. It consolidates the scattered admin touchpoints found across your six repositories into a single, unified control plane.

## 3. Problem Statement

Currently, the AIVO platform has:
- **6 separate repositories** with overlapping admin functionality (admin portals in `aivo-agentic-ai-learning-app`, district portals in `aivo`, super-admin in `aivo-platform`)
- **No unified operational dashboard** for platform-wide health, tenant management, or AI model governance
- **Fragmented billing/licensing** (M-Pesa in `aivo-platform`, licensing vault in `aivo-agentic-ai-learning-app`)
- **Distributed compliance controls** (COPPA in `aivo-agentic-ai-platform`, security audits in `aivo`, data deletion spread across repos)
- **No centralized observability** — monitoring configs exist in `aivo-v5` but aren't unified

## 5. Functional Requirements

### 5.1 Identity & Access Management (IAM)
*Sources: `aivo` (S2E-01 through S2E-12 implementation docs), `aivo-agentic-ai-learning-app` (RBAC, Auth integration docs)*

- **Multi-role RBAC**: Super Admin, Platform Admin, District Admin, School Admin, Support Agent
- **MFA enforcement** with recovery flows (already implemented in `aivo`)
- **Step-up authentication** for sensitive operations (implemented in `aivo`)
- **User impersonation** for support workflows (exists in `aivo-agentic-ai-learning-app`)
- **SSO/SAML** for enterprise district onboarding
- **Audit trail** for all admin actions

### 5.2 Tenant Management
*Sources: `aivo` (F1-N15-08 School/District Integration), `aivo-agentic-ai-learning-app` (District Portal docs), `aivo-platform` (SERVICE_CONSOLIDATION_MAP)*

- **District lifecycle**: Create → Configure → Onboard → Monitor → Archive
- **School management** within districts (hierarchy)
- **License/seat management** per tenant (connects to billing)
- **Custom branding/white-label** per district
- **Curriculum assignment** and approval workflows
- **District-level data isolation** and access controls

### 5.3 AI & Model Management
*Sources: `aivo-agentic-ai-platform` (AI-MODEL-MONITORING, AI-CONTENT-GENERATION), `aivo-agentic-ai-learning-app` (AGENTIC_AI_BRAIN, PERSONALIZED_BRAIN, MULTI_PROVIDER docs), `aivo-platform` (SPRINT_4_TASK_2_MODEL_MONITORING)*

- **Model registry**: Track all deployed AI models (Agentic Brain, inference engines, reasoning engines)
- **Multi-provider management**: OpenAI, Google Gemini, local models — with failover config
- **Model performance dashboard**: Accuracy, latency, cost-per-inference, drift detection
- **Trust Score monitoring** (implemented in `aivo-platform` Sprint 5)
- **Content generation oversight**: Review/approve AI-generated learning content
- **Brain training management**: Global and per-learner model training status

### 5.4 Learning Platform Operations
*Sources: `aivo-agentic-ai-learning-app` (ALL_PORTALS docs, BASELINE_ASSESSMENT docs), `aivo-agentic-ai-platform` (LEARNING-SESSION-SYSTEM, SEL-FRAMEWORK)*

- **Portal health status**: Admin, Parent, Teacher, District, Learner — all portal uptimes
- **Assessment management**: Baseline assessments, dynamic assessments, IEP tracking
- **Curriculum management**: District curriculum assignment, content library administration
- **Learning session monitoring**: Active sessions, completion rates, engagement metrics
- **SEL (Social Emotional Learning) program management**

### 5.5 Billing & Licensing
*Sources: `aivo-platform` (BILLING_CREDIT_PROCESSING, SPRINT_4_TASK_3_MPESA), `aivo-agentic-ai-learning-app` (PROMPT_64_LICENSING_VAULT)*

- **Subscription management**: Plans, tiers, seat counts per tenant
- **Payment gateway admin**: Stripe, M-Pesa, credit processing
- **Licensing vault**: License key generation, activation, expiry management
- **Usage metering**: AI API calls, storage, compute per tenant
- **Invoice generation** and payment history

### 5.6 Compliance & Security
*Sources: `aivo` (SECURITY docs, RISK_CONTROLS), `aivo-agentic-ai-platform` (COPPA-CONSENT, DATA-DELETION), `aivo-platform` (SECURITY_AUDIT_REPORT, COMPLIANCE_TEST_REPORT)*

- **COPPA consent management**: Parental consent status, data processing records
- **FERPA compliance dashboard**: Student data access logs, breach notifications
- **Data deletion requests**: GDPR/CCPA subject access request workflow
- **Security audit log viewer**: All admin actions, API access patterns
- **Vulnerability scanning status**: Integration with existing gitleaks/trufflehog configs

### 5.7 Infrastructure & Observability
*Sources: `aivo-v5` (docker-compose, k8s/, observability/), `aivo-platform` (OBSERVABILITY_OPERATIONAL_READINESS, HETZNER_DEPLOYMENT_GUIDE), `aivolearning` (infra/)*

- **Service health dashboard**: All microservices status (real-time)
- **Database health checks** (implemented in `aivo-platform` Sprint 4)
- **Deployment management**: Hetzner/K8s deployment status and rollback controls
- **Log aggregation viewer**: Centralized logs from all services
- **Performance metrics**: Response times, error rates, throughput per service
- **Load test results viewer** (infrastructure exists in `aivo-v5`)

### 5.8 Mobile App Management
*Sources: `aivo-platform` (MOBILE_APPS_PRODUCTION_READINESS, MOBILE_CRITICAL_BLOCKERS), `aivo-agentic-ai-learning-app` (MOBILE_APP docs, AIVO_PAD_MDM_UPDATE)*

```
┌─────────────────────────────────────────────────┐
│              Admin Dashboard (Next.js)           │
│   TypeScript · React · Tailwind · shadcn/ui      │
├─────────────────────────────────────────────────┤
│                 API Gateway (BFF)                │
│         Express/Fastify · GraphQL/REST           │
├──────────┬──────────┬──────────┬────────────────┤
│ Auth Svc │ Tenant   │ AI Mgmt  │ Billing Svc    │
│ (exists) │ Svc (new)│ Svc (new)│ (exists)       │
├──────────┼──────────┼──────────┼────────────────┤
│ Observ.  │ Complian.│ Learning │ Mobile Mgmt    │
│ Svc (ext)│ Svc (new)│ Ops (ext)│ Svc (new)      │
├──────────┴──────────┴──────────┴────────────────┤
│           PostgreSQL · Redis · S3                │
│        Prometheus · Grafana · Loki               │
└─────────────────────────────────────────────────┘
```

**Key decisions:**
- **Next.js frontend** — consistent with `aivo-v5` and `aivo-agentic-ai-learning-app` (both TypeScript-heavy)
- **Monorepo placement** — add as a workspace in `aivolearning` (your latest unified turborepo)
- **Reuse existing**: Auth (from `aivo`), Design System (from `aivo`), Prisma schemas (from `aivo-v5`), Observability stack (from `aivo-v5`)
- **Database**: Extend existing PLpgSQL schemas in `aivo-agentic-ai-platform` for audit logs and tenant config
