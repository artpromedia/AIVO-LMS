# AIVO Learner Experience Design Constitution (prepend to every learner-page prompt)

You are building/elevating AIVO's learner-facing experience in `apps/web-v2` (Next 15, React 19,
Tailwind v4, Radix, pixi.js) and `apps/mobile` (Expo / React Native). The user is a **neurodiverse
K–12 learner**. You are *elevating a real system, not greenfielding* (`learner-experience/
DESIGN-DIRECTION.md`): tokens, theming, sensory plumbing, and engagement data already exist. Build
on `@aivo/stage-ui`, `@aivo/learner-ui`, `@aivo/mobile-ui`, `@aivo/brand` (+ the `--lx-*` learner
token layer). Match the reference Stage screenshot.

North star: a learner should *want to come back tomorrow* — through delight, character, and progress
they can feel, never overload or compulsion. Build "a world with a host," not "a dashboard with
numbers." Bar = Duolingo / Khan Academy Kids, original IP, plus a **Calm mode they don't have**. If
a screen reads as "a dashboard," it isn't done.

Three non-negotiables on every screen:
1. **Neurodiverse-first is load-bearing** — honor My Workspace (Mood, Spacing, Font, Sound) and
   "breaks are good"; every delight element obeys them.
2. **Accessibility never regresses** — WCAG AA contrast (text uses `-ink` token variants; raw chroma
   is decorative-only ≥3:1), full keyboard nav, visible focus, `SkipLink`, `LiveRegion` SR
   announcements. A playful palette is no excuse for low contrast.
3. **No dark patterns** — grace on streaks; no FOMO, shame, countdowns, or loot-box mechanics.

Mandatory behaviors:
- **One primary action per screen** (`PrimarySlot`); progressive disclosure.
- **Audio-first** — read-aloud / Play-sound always present; TTS via the contract (6 voices, speed
  0.5–1.5).
- **Functioning-level adaptation** (`FlVariantProvider`, `FL_PROFILES`) — density + choice count
  scale from STANDARD (full, ≤5) to PRE_SYMBOLIC (single, ≤2); never exceed the learner's
  `maxChoices`.
- **Sensory + Mood** — `data-sensory-mode` (standard/calm/high-contrast → motionScale 1/0.5/0) and
  Mood (Calm/Balanced/Energizing → `--lx-motion` 0.45/1/1.2). Calm genuinely turns the dial down;
  keep contrast a separate toggle (don't let "Energizing" kill motion). Respect
  `prefers-reduced-motion`; PRE_SYMBOLIC = no motion.
- **AAC + switch access** — touch/switch/eye-gaze/head-pointer with scan/dwell timing
  (`@aivo/accessibility-contract`, `@aivo/aac-bridge`, mobile SwitchScanOverlay); every custom
  gesture has a one-tap alternative.
- **Breaks** — a calm, non-punitive break affordance (`BreakCloud`) per the learner's break
  interval; never gate or shame.
- **Age tiers** (`TIER_THEMES` / `gradeToTier`) — dignified for older kids, gentle for younger.
- **Theming** via `data-*` attributes + `@aivo/brand` tokens + `--lx-*`; no raw hex; never fork the
  pipeline. Web (CSS/Tailwind) and mobile (RN) render from the same contract.
- **Original IP** — host/mascot + tutor characters are expressive but obey every sensory setting;
  upgrade the crude placeholder art.

For each page: don't jump to code. First return (a) the screen-state map (incl. empty/loading/error/
celebration and the PRE_SYMBOLIC variant), (b) the interaction + audio/AAC spec, (c) the visual
direction in tokens. Preview in `app/design-system/*` (dev-only). Pause for approval.

  activities; strengths-based throughout.

  no deficit framing or pseudo-grade-gaps.
Reuse: `@aivo/stage-ui`, `@aivo/learner-ui`, `@aivo/adaptive-baseline`, baseline BFF
(start/answer/complete).
DoD-delta: zero child-facing scores/failure; frustration → break/modality; fully playable at
PRE_SYMBOLIC (single choice + symbol/AAC); audio-first; parent handoff strengths-first.

# FOUNDATION PROMPT — The Unified Stage (build this FIRST; every learner session renders through it)
Inherits: the Learner Experience Design Constitution + the "single shared surface" clause.

Grounding / mandate:
- The shared Stage engine exists: `@aivo/stage-ui` (the `Beat` / `InteractionType` / `SessionState` /
  `SensoryProfile` contract + StageLayout, StageContent, BeatPreview, ResponseZone, ProgressPath,
  TutorCharacter, StageBreakCloud, CelebrationOverlay) and `@aivo/stage-runtime` (`SessionMachine`,
  `useSessionFlow`, sensory adapters, `useTTS`, `useSpeechInput`, `voiceMatch`); mobile via
  `MobileStageRuntime`.
- The **lesson player already runs on it** (`apps/web-v2/app/learner/lesson-runs/[lessonRunId]/
  player/*`). The **baseline does NOT** (`/learner/baseline/*`, mobile `(learner)/baseline/run` use a
  separate UI). **Removing that seam is the whole job.**

Goal: harden ONE Stage that renders every learner session identically, so a child's path from first
engagement (baseline) into daily learning is literally the same surface — same host, beats, My Words
rail, breaks, celebration, and controls. The child never crosses a "now it's a test / now it's
learning" boundary.

Deliverables:
1. **The Stage shell** (the reference screenshot) — `StageLayout`: header (subject·level, points,
   profile), left `ProgressPath` (the beats, e.g. Listen → Choose → Check), center `StageContent`
   (one prompt + audio-first Play-sound + `ResponseZone`), right "My Words" rail (Help/hint,
   Again/replay, I-know/self-pace), host `TutorCharacter`, `StageBreakCloud` ("Take a break"), footer
   Back/Next + step dots.
2. **The Beat model** — formalize `Beat` + `InteractionType` as the atomic unit and the response set
   every session draws from: single/multi choice (≤ FL `maxChoices`), audio-match, voice
   (`useSpeechInput` / `voiceMatch`), draw/handwriting, sequence/order, symbol/AAC select. Each beat
   = prompt + audio + interaction + feedback.
3. **The session contract** — a `kind` (`baseline` | `lesson` | `homework` | `quest`) plus a
   content/policy adapter interface (next-beat, accept-answer, on-affect, on-complete) so any source
   plugs in WITHOUT touching the UI. `SessionMachine` / `useSessionFlow` drive transitions
   (advance / remediate / say / end_early).
4. **Cross-cutting behaviors wired once, inherited by all sessions:** audio-first TTS (contract
   voices/speed), AAC + switch (touch/switch/eye-gaze/head-pointer + scan/dwell via
   `@aivo/aac-bridge`), FL adaptation (density + maxChoices via `FlVariantProvider`), sensory + Mood
   (motionScale / `--lx-motion`, reduced-motion, PRE_SYMBOLIC = no motion), breaks per interval,
   `LiveRegion` beat announcements, gentle no-shame retry, Mood-aware celebration.
5. **Convergence task** — migrate the baseline run (web `/learner/baseline/[baselineId]`, mobile
   `(learner)/baseline/run`) onto this exact Stage. After this, baseline and lessons share ONE
   renderer.

Definition of done:
- Baseline and lesson sessions render through the SAME `StageLayout` / `MobileStageRuntime` — verified
  no separate baseline UI remains.
- One Beat/InteractionType set powers both; switching `kind` changes only content + policy, never
  layout/host/controls.
- Audio-first, AAC/switch, FL (incl. PRE_SYMBOLIC), sensory/Mood, breaks, and LiveRegion live in one
  place and apply to every session kind.
- Matches the reference screenshot at STANDARD; degrades correctly to PRE_SYMBOLIC; no
  timers/countdowns; no shame.
