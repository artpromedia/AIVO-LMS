## TASK 1: Implement Email-Based MFA via Postmark

### Current State
- MFA is **NOT implemented** anywhere in the codebase despite the compliance dashboard (`apps/web/src/app/dashboard/admin/compliance/page.tsx`) claiming `{ label: "Multi-Factor Authentication (MFA)", status: true }` — this is false
- Login routes at `services/identity-svc/src/routes/auth.ts` (`/api/auth/login`, `/api/auth/admin-login`, `/api/auth/google`) issue JWT immediately after password check — no second factor
- The `users` table has no `mfa_enabled` or `mfa_method` columns
- Postmark is fully operational in `services/comms-svc/src/lib/postmark.ts` with `POSTMARK_API_TOKEN` configured
- The Hetzner deployment guide references `mfa-encryption-key` in secrets but it's never consumed
- i18n has `"two_factor": "Two-Factor Authentication"` string in settings namespace but no UI uses it

### Requirements

#### 1.1 Database Changes (packages/db)
- Add columns to `users` table: `mfa_enabled BOOLEAN DEFAULT false`, `mfa_method VARCHAR(20) DEFAULT 'email'`
- Create new `mfa_codes` table:
  - `id` UUID PK
  - `user_id` UUID FK → users.id ON DELETE CASCADE
  - `code` VARCHAR(6) NOT NULL
  - `purpose` VARCHAR(20) — 'login' | 'step_up' | 'setup'
  - `expires_at` TIMESTAMPTZ NOT NULL
  - `used_at` TIMESTAMPTZ (null = unused)
  - `attempts` INT DEFAULT 0
  - `created_at` TIMESTAMPTZ DEFAULT NOW()
- Add indexes on `user_id` and `expires_at`
- Create and run Drizzle migration

#### 1.2 MFA Service (services/identity-svc/src/services/mfa.ts)
- `generateOTP()` — cryptographically secure 6-digit code using `crypto.randomInt(100000, 999999)`
- `createMFACode(db, userId, purpose)` — invalidate prior unused codes for same user+purpose, insert new code with 10-minute expiry, return code string
- `verifyMFACode(db, userId, code, purpose)` — find valid unused unexpired code, enforce max 5 attempts, increment attempts on wrong code, mark used on success, return `{ valid, error? }`

#### 1.3 MFA Email Template (services/comms-svc)
- Create `services/comms-svc/src/lib/templates/mfa-code.ts` — renders branded HTML email with the 6-digit code, AIVO purple (#7C3AED), Fredoka heading, Nunito body, 10-minute expiry notice
- Put the code in subject line: `"${code} is your AIVO verification code"`
- Register internal endpoint `POST /api/comms/internal/mfa-code` secured by `x-internal-key` header matching `process.env.INTERNAL_API_KEY` — accepts `{ to, code, name }`, calls `sendEmail()` with rendered template and tag `"mfa-verification"`

#### 1.4 Identity Service Routes (services/identity-svc/src/routes/auth.ts)
Modify existing login flow and add new endpoints:

**Modify `/api/auth/login`:**
- After successful password verification, check `user.mfaEnabled`
- If MFA enabled: generate code via `createMFACode()`, send via comms-svc internal endpoint, issue short-lived `mfaToken` JWT (15min, payload: `{ sub: user.id, purpose: "mfa" }`), return `{ mfaPending: true, mfaToken, mfaMethod: "email" }` — do NOT issue access token
- If MFA disabled: existing behavior (issue access token immediately)

**Modify `/api/auth/admin-login`:**
- **Force MFA for all admin roles** (PLATFORM_ADMIN, DISTRICT_ADMIN, SALES, MARKETING, CUSTOMER_CARE, SUPPORT, FINANCE, DEVOPS)
- If user doesn't have `mfaEnabled`, auto-enable it: `UPDATE users SET mfa_enabled = true`
- Always go through MFA flow — generate code, send email, return `mfaPending`

**New `POST /api/auth/verify-mfa`:**
- Body: `{ mfaToken: string, code: string }`
- Verify mfaToken JWT (check `purpose === "mfa"`, check not expired)
- Call `verifyMFACode()` with the code
- On success: issue real accessToken with `mfaVerified: true` in payload, create session, set refreshToken cookie (same pattern as existing login)
- On failure: return 401 with error message

**New `POST /api/auth/mfa/enable`:**
- Requires valid Bearer token
- Sends setup verification code to user's email
- Returns `{ message: "Verification code sent", mfaMethod: "email" }`

**New `POST /api/auth/mfa/confirm-enable`:**
- Body: `{ code: string }`
- Requires valid Bearer token
- Verifies code with purpose "setup"
- Sets `mfa_enabled = true` on user record

**New `POST /api/auth/mfa/disable`:**
- Body: `{ password: string }`
- Requires valid Bearer token
- Verifies password before disabling
- Sets `mfa_enabled = false`

**New `POST /api/auth/mfa/resend`:**
- Body: `{ mfaToken: string }`
- Validates mfaToken, generates new code, sends via Postmark
- Rate limit: max 3 resends per mfaToken session

#### 1.5 Frontend — Web App MFA Flow (apps/web)
- **Login page** (`apps/web/src/app/(auth)/login/page.tsx` or similar): After login API returns `{ mfaPending: true }`, navigate to MFA verification screen
- **MFA Verification page**: 6-digit code input (individual digit boxes, auto-advance), countdown timer showing expiry, "Resend code" button (disabled for 30s after send), "Use a different method" placeholder for future TOTP, calls `POST /api/auth/verify-mfa`, on success store token and redirect to dashboard
- **Settings Security section**: Add MFA toggle in the security settings page, wire to `/api/auth/mfa/enable` → code entry → `/api/auth/mfa/confirm-enable`, wire disable to `/api/auth/mfa/disable` with password confirmation modal
- **Admin login page**: Same MFA verification flow, always shown after password step

#### 1.6 Frontend — Mobile MFA Flow (apps/mobile)
- After login returns `mfaPending`, navigate to MFA verification screen
- Same 6-digit input UX adapted for React Native
- Settings screen MFA toggle

#### 1.7 Fix Compliance Dashboard
- In `apps/web/src/app/dashboard/admin/compliance/page.tsx`, the `securityControls` array has `{ label: "Multi-Factor Authentication (MFA)", status: true }` — this should dynamically reflect actual MFA adoption rate or at minimum only show `true` after implementation ships

#### 1.8 Cleanup Cron
- Add a scheduled job (can be a simple setInterval in identity-svc or a DB-level pg_cron) to delete expired mfa_codes older than 1 hour: `DELETE FROM mfa_codes WHERE expires_at < NOW() - INTERVAL '1 hour'`
